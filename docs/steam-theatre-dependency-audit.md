# STEAM Theatre beta: dependency audit

Audit performed 27 November 2026 against the npm advisory registry and the lockfile. Initial `npm audit` reported 24 affected package entries: 11 high, 11 moderate and 2 low; `npm audit --omit=dev` reported zero. These are package counts, not 24 independent exploitable paths. `npm audit fix` was run without `--force`; a repeat audit reports zero known findings for both the full and production dependency sets. This is a point-in-time registry result, not a guarantee of security. MediaPipe remains pinned at 0.10.17 and its model/WASM remains locally hosted.

## Original paths and exposure

All original affected paths were development dependencies, not dependencies in `npm audit --omit=dev`:

- **Vite dev server:** direct `vite` 7.3.1, `@vitejs/plugin-react -> vite`, and `vitest -> vite`. The reported advisories included file reads and Windows launch-editor issues (for example [GHSA-p9ff-h696-f583](https://github.com/advisories/GHSA-p9ff-h696-f583) and [GHSA-587h-7wmj-h5pm](https://github.com/advisories/GHSA-587h-7wmj-h5pm)). These are relevant when running an accessible dev server or invoking its editor integration; a static production bundle does not expose that dev server. Updated to 7.3.8.
- **Build processing:** `@vitejs/plugin-react -> @babel/core -> browserslist -> baseline-browser-mapping`, and `vite -> esbuild`, `vite -> postcss -> nanoid/source-map-js`, and `vite -> fdir/tinyglobby -> picomatch`. The issues include crafted source maps, build inputs and glob patterns. They matter when untrusted files or inputs are processed during a build; no corresponding browser endpoint is introduced by these packages. Resolved by compatible lockfile updates.
- **Lint tooling:** `eslint -> minimatch -> brace-expansion`, `eslint -> @eslint/eslintrc -> js-yaml`, `eslint -> file-entry-cache -> flat-cache -> flatted`, `eslint -> @humanfs/node`, `typescript-eslint -> @typescript-eslint/{parser,eslint-plugin,type-utils,typescript-estree,utils} -> minimatch -> brace-expansion`, and `eslint-plugin-react-hooks -> zod`. These advisories concern tool input, e.g. malicious glob/YAML inputs, and run in the developer or CI environment. Resolved by compatible lockfile updates.
- **Tests:** `vitest -> @vitest/mocker` and `vitest -> picomatch`. The mock-registration advisories affect the Vitest server with its relevant exposure, rather than deployed static assets. Vitest updated to 4.1.12.
- **Asset processing:** direct development dependency `sharp` 0.35.3 contained vulnerable native image libraries ([GHSA-rgj7-g3m4-5g8c](https://github.com/advisories/GHSA-rgj7-g3m4-5g8c), [GHSA-wq5f-xc86-pv6w](https://github.com/advisories/GHSA-wq5f-xc86-pv6w)). The repository invokes it in local asset-generation scripts, so processing untrusted image files was the relevant risk, not normal use of the published website. Updated to 0.35.5.

Remaining registry findings: **none at the time of this audit**. No claim is made that a production deployment is invulnerable; rerun `npm audit` and `npm audit --omit=dev` as advisories and dependencies change. Keep development servers private and use trusted inputs in build and asset-processing workflows.
